## Um pacote, quatro visões

Um único pacote local, um único índice de dados local — e quatro formas de lê-lo.
Cada superfície analisa os mesmos logs de sessão na sua própria máquina, então o
painel no navegador, o terminal, a barra de menu e a statusline do seu agente
sempre concordam entre si.

| Visão | O que é | Quando recorrer a ela |
|---|---|---|
| **[WebUI](#webui)** | O painel completo: Overview, Sessions, Stats, Report, Quota, Servers | Você quer o panorama completo, gráficos e detalhamento por nível |
| **[TUI](#painel-no-terminal-tui)** | `tokdash tui` — Overview, Report e Quota no terminal | Você vive no terminal e quer os números sem navegador |
| **[Companion](#app-de-barra-de-status-companion)** | App nativo de barra de menu (macOS) / área de notificação (Windows) | Você quer o gasto do dia e a cota visíveis o dia todo, com o painel fechado |
| **[Statusline](#statusline)** | Um item de tokens/custo ao vivo dentro da statusline do seu agente | Você quer o contador de custo exatamente onde digita |

### WebUI

O painel é uma página única servida pelo app FastAPI local: detalhamentos exatos
de tokens de entrada / cache / saída, tabelas por ferramenta e por modelo, um
heatmap de contribuições, um **Report** semanal/mensal/anual, janelas de **Quota**
por provedor com contagens regressivas de reset, e uma aba **Servers** que
combina e compara várias máquinas. Clique em qualquer captura para abrir a
[demo ao vivo](https://tokdash.github.io/demo/).

### Painel no terminal (TUI)

Prefere ficar no terminal? `tokdash tui` abre as abas **Overview**, **Report**
e **Quota** sem navegador, lendo o mesmo índice local (e o banco de dados
compartilhado em disco quando um `tokdash serve` está rodando ao lado).

```bash
tokdash tui
```

<details>
<summary>Teclado</summary>

| Tecla | Ação |
|---|---|
| `q` | Sair |
| `r` | Atualizar a aba atual |
| `1` / `2` / `3` | Alternar para Overview / Report / Quota |
| `t` `w` `m` `y` `a` | Pular direto para o período (ambas as abas de período; `t`/`a` só no Overview) |
| `p` | Próxima janela de tempo (ciclo somente para frente) |
| `[` / `]` | Recuar / avançar um período calendárico inteiro — nunca para o futuro |
| `0` | Voltar para hoje |
| `u` | Sondar a cota (somente aba Quota) |
| `?` | Painel de ajuda com todas as teclas |

</details>

<details>
<summary>CLI de relatório de execução única</summary>

Para um relatório de execução única que você pode redirecionar por pipe ou usar
em scripts:

```bash
tokdash report --period week
```

O período é uma flag, não um argumento posicional. Valores aceitos: `today` (o
padrão), `week`, `month`, `year`, `all`, um número de dias ou o atalho
`Nd/Nw/Nm/Ny`; `week`, `month` e `year` são as mesmas janelas alinhadas ao
calendário exibidas na aba Report do painel web. O `tokdash report` também
aceita `--json`, `--pretty` e `--output <file>`, seguindo as mesmas convenções
do `tokdash export`.

</details>

## Início rápido

### Suporte por plataforma

- **Linux (incluindo WSL2):** suportado
- **macOS:** suportado
- **Windows (nativo):** experimental

**Pré-requisitos:** Python **3.10+** e um ou mais
[clientes suportados](docs/reference/SUPPORTED_CLIENTS.md).

### Instalação

Instalação isolada recomendada:

```bash
pipx install tokdash
```

Se você não usa pipx:

```bash
python3 -m pip install --user tokdash
```

### Primeira execução

Execute o assistente de onboarding:

```bash
tokdash setup
```

O assistente configura um serviço em segundo plano reversível em nível de usuário quando a
plataforma suporta, e então imprime a URL do painel (padrão: `http://127.0.0.1:55423`). Se
não houver nenhum gerenciador de serviços suportado, ele registra o estado da configuração e
imprime orientações de execução em primeiro plano. Usa padrões localhost-first, não requer
`sudo` para o serviço local e mantém seu histórico de uso, a menos que você desinstale depois
com `--purge`.

Para uma configuração não interativa a partir de um agente, script ou bundle, execute
`tokdash setup --auto --json`; para pré-visualizar o que a configuração mudaria,
`tokdash setup --dry-run`. Para expor o painel explicitamente em todas as interfaces de rede
com a gravação desabilitada, execute `tokdash setup --bind 0.0.0.0`; revise primeiro o
[guia de acesso remoto](docs/guides/REMOTE_ACCESS.md).

Depois verifique a instalação:

```bash
tokdash doctor
```

O `doctor` verifica o runtime, o serviço em segundo plano, a porta configurada, os caminhos
de dados e o estado da verificação de atualizações. Use `tokdash doctor --json` para
automação.

### Atualizar ou remover

```bash
tokdash update       # faz upgrade do runtime gerenciado e reinicia o serviço quando possível
tokdash uninstall    # reverte exatamente o que o setup criou; mantém o histórico de uso por padrão
```

O `update` só dirige métodos de instalação que o Tokdash pode gerenciar com segurança. Se o
seu runtime foi instalado por um gerenciador de pacotes que o Tokdash não controla, ele
imprime as orientações manuais exatas em vez de modificar esse ambiente.

<details>
<summary>Instalações existentes: migração de antes da v1.0</summary>

Se você instalou o Tokdash antes do fluxo de onboarding, faça upgrade primeiro:

```bash
pipx upgrade tokdash
# ou: python3 -m pip install --user -U tokdash
```

Depois execute `tokdash doctor` e `tokdash setup` quando quiser que o Tokdash gerencie o serviço
em segundo plano. Se você já tem um serviço systemd ou launchd escrito à mão, o setup **não**
o substitui em silêncio: por padrão ele recusa arquivos `tokdash.service` / plist sem marca.
Continue gerenciando esse serviço você mesmo, remova-o antes do setup, ou execute
`tokdash setup --force` depois de conferir `tokdash setup --dry-run`. O `--force` também lida
com serviços anteriores a 1.0 que já ocupam a porta `55423` mas não expõem a nova impressão
digital `/health`: ele reescreve e reinicia o `tokdash.service` existente. Use
`tokdash setup --no-service` para pular a criação do serviço.

Se a sua configuração atual usa um interpretador conda/sistema/pip de usuário e você quer que
o `tokdash update` gerencie futuros upgrades, migre o serviço para o venv de propriedade do
setup do Tokdash:

```bash
# Faça upgrade do comando tokdash que você está prestes a executar, por exemplo:
python3 -m pip install --user -U tokdash
# ou, para uma instalação no conda base:
conda run -n base python -m pip install -U tokdash
tokdash setup --runtime venv --force
tokdash doctor
```

Isso mantém seu histórico de uso em `~/.tokdash`, reescreve o serviço de usuário para executar
`~/.tokdash/runtime/python-venv/bin/python -m tokdash` e permite que futuros `tokdash update`
façam upgrade desse venv gerenciado e reiniciem o serviço. Se você instalou com pipx, pode
manter o runtime do pipx e fazer upgrade com `tokdash update` ou `pipx upgrade tokdash`.

</details>

### Alternativa em primeiro plano

Se você só quer um processo pontual em primeiro plano:

```bash
tokdash serve
```

Abra `http://127.0.0.1:55423`. Use `tokdash serve --port <porta>` se a porta padrão estiver
ocupada. Por padrão, o `tokdash serve` abre o painel no seu navegador uma vez na inicialização;
passe `--no-open` para desabilitar. Um `tokdash` sem comando apenas mostra a ajuda de comandos
e sai — não inicia mais o `tokdash serve` pelas suas costas.

Para todos os detalhes do onboarding — escolhas de runtime, comportamento WSL/systemd,
launchd do macOS, Tailscale, bundle, verificações de atualização e a semântica de
desinstalação segura — consulte **[`docs/guides/ONBOARDING.md`](docs/guides/ONBOARDING.md)**.
Para acesso remoto através do Tailscale Serve, encaminhamento SSH ou um vínculo de rede
explícito, consulte **[`docs/guides/REMOTE_ACCESS.md`](docs/guides/REMOTE_ACCESS.md)**.

## Funcionalidades

- **Contagem exata de tokens**: detalhamento de tokens de entrada/saída/cache
- **Explorador de sessões**: detalhamento por sessão
- **Calendário de contribuições**: heatmap 2D + visão isométrica 3D com métricas de Tokens/Cost/Messages
- **Aba Report**: relatório da sua própria atividade de agentes por semana, mês e ano corrente, com um cartão compartilhável para cada nível de detalhe. Cada exportação grava um PNG claro e um escuro
- **Aba Quota**: barras de janela de assinatura com contagem regressiva de reset para nove provedores. As janelas do Codex funcionam direto dos logs locais; a maioria das outras origens exige [polling ao vivo](#acompanhamento-de-cota-opcional) opt-in
- **Painel no terminal** *[novo]*: `tokdash tui` — Overview, Report e Quota no terminal, sem navegador
- **App de barra de status Companion**: gasto e cota de assinatura na barra de menu do macOS ou na área de notificação do Windows — para Windows na [Microsoft Store](https://apps.microsoft.com/detail/9ppnmpdq8b52)
- **Integração com statusline**: um indicador de uso de tokens ao vivo dentro da statusline do Claude Code (ou de qualquer agente que consiga acionar um endpoint HTTP local)
- **Visões multi-servidor**: adicione servidores Tokdash de WSL, macOS e outros nas Configurações; combine o uso de qualquer seleção mantendo a cota agrupada por máquina. Veja [acesso remoto](docs/guides/REMOTE_ACCESS.md).
- **Temas e acabamento do app**: 17 temas de estilo, modo claro/escuro, suporte a instalação PWA, UI em seis idiomas

## Acompanhamento de cota (opcional)

A aba Quota mostra janelas de utilização de assinatura e cronômetros de reset para
**nove provedores**. As janelas de 5 horas/semana do Codex funcionam direto dos
logs locais (trate-as como uma estimativa); o consumo exato do Codex e todos os
outros provedores — Claude Code, Antigravity, MiniMax, Kimi Code, Grok, Z.ai,
OpenCode Go, Command Code — vêm do **polling ao vivo opt-in**: o Tokdash chama o
próprio endpoint de cota de cada provedor com o login que sua CLI já tem.
Desligado por padrão, consentimento por provedor, resultados mantidos no banco de
dados local.

Os comandos de consentimento, o interruptor geral, a cadência de polling e as
notas de credenciais por provedor estão em
**[`docs/reference/QUOTA.md`](docs/reference/QUOTA.md)**.

## Nota sobre a precisão do custo

As contagens de tokens dependem do que cada cliente registra localmente. Os custos são calculados por padrão a partir do banco de preços incluído (`src/tokdash/pricing_db.json`), ou da sua sobrescritura de preços salva do painel em `<data_dir>/pricing_db.json` quando presente. Em qualquer caso, podem ficar atrás do preço real do provedor — use como estimativa e verifique contra sua fonte de faturação se importar.

## Retenção do histórico

> [!IMPORTANT]
> **Mantenha seu histórico.** O Claude Code e o Gemini CLI excluem por padrão sessões locais com mais de ~30 dias, então os meses anteriores do Tokdash podem encolher em silêncio.

O Tokdash lê os logs de sessão **locais** de cada cliente; o índice SQLite local
não pode recuperar logs excluídos antes de serem indexados. Apenas dois clientes
suportados excluem sessões antigas por padrão, e ambos são uma correção de uma
linha:

- **Claude Code**: adicione `{ "cleanupPeriodDays": 3650 }` ao seu `~/.claude/settings.json` (e a qualquer `CLAUDE_CONFIG_DIR` alternativo).
- **Gemini CLI**: defina `{ "general": { "sessionRetention": { "enabled": false } } }` no `~/.gemini/settings.json` (configurações de workspace sobrepõem as de usuário).

Todos os outros clientes suportados mantêm o histórico indefinidamente por padrão. Para a
pesquisa completa por cliente, detalhes da correção e o que o índice SQLite local preserva
e não preserva, veja **[docs/reference/HISTORY_RETENTION.md](docs/reference/HISTORY_RETENTION.md)**.
