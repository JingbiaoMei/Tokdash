Review notes

Why Today is the primary content

The three product questions are "what did I spend today", "how am I tracking this month", and "which quota is closest to its limit". Today answers the first and most frequent question and is the number a user checks habitually; month and quota are context. Making month or quota primary would optimize for a weekly check at the cost of the several-times-daily one. The hero carries its context (tokens, messages, comparison) on the same lines so the big number never floats alone.

Which quota windows the main surface shows

The main surface shows low windows only: a subscription window appears when it drops below its low-quota threshold — 5-hour windows at 20% remaining, weekly windows at 10% remaining. Both thresholds are configurable in Settings (macOS app menu → Quota Alert Thresholds…). In practice this means the 5-hour window is the one that earns a slot when it runs hot, while a weekly window only interrupts when it is genuinely close to exhaustion. At most two entries are shown, sorted by lowest remaining percentage; when nothing is low the section collapses to one quiet line, so Today is never competing with healthy quota.

The toggle is labelled Low / All, not "Urgent": the section is a filtered view of current state, not an alarm list, and the thresholds already carry the urgency semantics. All lists every detected window grouped by provider (provider order as detected, window order within a provider as returned by the API) — not ranked by usage, because grouping answers "how is each subscription doing" faster than a flat ranking. The list is capped at four visible rows with the fifth row peeking in, then scrolls — it must never stretch the surface.

Everything quota-related lives inside the status-bar surface; there is no separate subscriptions window. Two production notes: the prototype's thin custom scrollbar stands in for the platform's native/overlay scrollbar (NSScroller overlay style on macOS, WinUI ScrollViewer defaults on Windows) — do not ship custom scrollbar styling. Per-window detail (plan tier, data source, exact reset time) stays one click away in the full dashboard rather than expanding rows here.

What could be removed if the surface feels crowded

  • First: the activity line ("Most used today"). It is interesting, not actionable, and the spec already marks it as first to cut.
  • Second: the month context line, if Today plus quota answers the check-in. It survives in the Empty state where it is the only real data.
  • Third: nothing else — the "price estimate, not a provider invoice" disclaimer under the hero was already cut for noise; the dashboard remains the place for that caveat.

Meaningful differences between the two concepts

  • Anchoring and shape: macOS is a MenuBarExtra(.window) floating panel below the menu bar with 14px continuous corners and hairline separators. Windows is a light-dismiss Acrylic flyout anchored to the taskbar corner with 8px corners and a distinct footer band.
  • Materials: the production macOS app uses the system's Liquid Glass material (macOS 26) through standard SwiftUI controls — this prototype approximates it with CSS translucency and deliberately does not try to fully demonstrate Liquid Glass. Windows uses Acrylic with a noise layer and lower tint, plus a solid fallback for battery saver and high contrast.
  • Typography: SF Pro sizing/weights (650-weight hero, 11px uppercase kickers) vs. Segoe UI Variable (600-weight hero, looser line-height).
  • Commands: macOS puts Settings and Quit in an NSMenu-style dropdown from the header gear plus a quiet Quit in the footer; Windows puts Exit in the tray right-click menu and keeps the flyout commands to Open Dashboard + Refresh. Neither is a recolor of the other.
  • Controls: macOS buttons are capsule-adjacent push buttons with a 0.5px border; Windows buttons are 4px-radius with the characteristic bottom border edge. Focus rings follow each platform's convention.

Decided since the first draft

  • Quota display: main surface shows only windows below their low-quota threshold, max two entries. Defaults: 5-hour 20%, weekly 10%; both configurable in Settings.
  • Full quota list: a Low / All toggle inside the surface; All is grouped by provider, capped at four rows, and scrolls. No separate subscriptions window — everything stays in the status-bar surface.
  • Naming: "Low" over "Urgent" — the section filters state; it is not an alarm list.
  • Branding: the concepts use the Tokdash logo from docs/assets, recreated inline so the file stays self-contained. macOS gets a monochrome template variant for the menu bar (per platform convention); Windows uses the color logo with a white interior so it stays readable on light and dark taskbars. Production should ship real rendered assets at each required size rather than scaled SVG.
  • Contribution heatmap: rejected. The dashboard's Stats tab already provides one; the companion answers three glance questions, and a heatmap answers none of them. It would also need year-range data the companion contract deliberately avoids fetching, and it conflicts with the "no decorative charts" direction.

Open product decisions

  • Should the hero stay spend-first, or switch to quota-first when any window crosses its low threshold?
  • macOS optional menu-bar text ($3.42 beside the icon) — MVP or later setting?
  • Accept a manually configured Tailscale/HTTPS base URL in MVP, or loopback only?
  • Should crossing a low-quota threshold produce an opt-in notification, or stay display-only in MVP (current plan: display-only)?
  • Does the activity line survive user testing, or is it noise?
  • Should the busy/offline banner replace the hero or sit above dimmed last-good data (currently: above, data dimmed)?
