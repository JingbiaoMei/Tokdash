## 2.6.12 - 2026-10-09

### 新增

- 打开 OpenCode 会话现在会填充转录时间线和右侧详情抽屉，而不再提示没有存储转录。Tokdash 以只读方式读取 OpenCode 数据库中的消息元数据（角色、时间、模型、token 与字符计数、是否带有推理或工具调用）以及工具元数据（名称、状态，以及是否带有参数）。读取的仅限元数据：你的提示词、回复、推理内容和工具输出都不会离开数据库。
- Sessions 页的客户端筛选现在会在名称旁显示各工具的图标，行宽不够时自动收成只剩图标，于是十几个工具也能排成一行并保持可读。
- 新增的架构页面完整走过一条用量记录的路径：从本地客户端日志到解析器、用量数据库与计价，再到 API、终端仪表盘和 statusline。Quota 指南也补上了后台轮询及其重置边界采样的时序图。
- 配置参考补齐了 23 个此前只存在于代码中的 TOKDASH_* 设置，涵盖后台预热、会话与解析、配额轮询、终端仪表盘以及更新检查。
- 六份 README 现在都带有 CI 状态徽章与当前的 PyPI 版本。
- 新的 PR 会自带模板，其中包含测试章节与检查清单；pytest 也移进了开发依赖，一次安装即可跑完整套测试。
- /openapi.json 中的 OpenAPI schema 现在会自我描述：带版本、许可证与六个 tag，全部路由都有 tag，多数还有一行摘要。
- 新增四个模型的计价：gpt-6.1-sol-pro、claude-haiku-5.5、mistral-large-4-0 和 gemini-nano-banana-2.1。

### 调整

- 仪表盘不再提供 Swagger UI 与 ReDoc 页面。这两个页面会从不带完整性校验的公共 CDN 拉取 JavaScript，而加载在仪表盘同源之下的脚本完全可以像仪表盘本身一样去索取写入令牌。/openapi.json 的纯 JSON schema 保留，OpenAPI 工具照常可用，API.md 仍然是给人阅读的参考。
- Freebuff 换上的是它真正的标志，而不是占位字母，颜色也改成了该站点自己在用的绿色。Muse Code 保留字母方块，但仪表盘图标与 README 徽章统一为同一个蓝，支持客户端列表也不再漏掉它。
- 贡献指南改为按 CI 的方式安装完整的开发依赖，补上了 Windows 的激活命令，并让源码运行使用独立的数据目录，这样开发中的版本就不会去迁移你真正的用量数据库。

### 修复

- Overview 的六条 sparkline 现在画的是你每日记录的真实用量，不再是一条对任何用户、任何日期范围、任何服务器都长相同的装饰曲线。曲线只由页面已经加载的数据构建，因此不额外发请求；缓存命中率曲线按分子求和，而不是对每日百分比取平均；top model 曲线跟着卡片点名的那个模型走；数据未覆盖的日子显示为空缺而不是零；确实无法诚实绘制时，卡片会用六种语言说明原因，而不是随手画出一个形状。
- Devin CLI 现在能从真实的 sessions 数据库中读出用量。此前的库里，token 计数、模型与行 id 都存放在解析器没有读取的字段中，导致真实安装显示不出任何用量。
- 在超宽显示器上，仪表盘内容现在居中于侧边栏右侧的可用空间，而不是紧贴着侧边栏。1920px 及以下的布局保持不变。
- 三个命令行错误现在会告诉你下一步该做什么：verify 失败会指向 db resync，未知的 db 操作会列出有效选项，--port 非法时会报告它真正遇到的问题。

## 2.6.11 - 2026-10-05

### 新增

- 把鼠标悬停在 Overview 的每张 KPI 卡片上，现在都会读出四舍五入之前的精确数值：完整的 token 总数、带上单位的消息数、精确到秒的 agent 时长、保留两位小数的缓存命中率，以及不再被截断的模型名称。读出的气泡沿用该卡片自身的配色，鼠标移过去也不会消失。Cost 卡片特意没有这一项：费用在到达浏览器之前就已经四舍五入到美分，多出来的几位只是虚假的精度。
- 仪表盘中不可见的文本现在也翻译了：aria-label、工具提示、会话搜索框的占位文字以及浏览器标签页标题，六种语言全部覆盖。使用读屏软件的用户不再会在翻译好的界面里听到英文，其中也包括 Quota 页的提供方菜单 —— 它此前由代码直接写死，在任何语言下都只会用英文播报。

### 调整

- Overview 与 Stats 两个页面去掉了一处重复的数字，间距也统一了。Token Composition 不再在图例正上方打印一个与它相同的 Cache Saved 总数；顶部区块与下方第一行卡片之间的距离，现在与页面其余部分保持一致；Stats 的卡片网格也分别设定了行距与列距，不再混用两套间距。
- README 支持客户端条幅里的 Freebuff 图标导出时没有保留透明度，在 GitHub 的深色主题下就像垫着一块白色底板。现在换回了带透明边角的版本，并新增一条检查，要求所有客户端图标都保留 alpha 通道。

### 修复

- DeepSeek Harness 此前丢失的用量现在会被计入。compaction 事件自带那次摘要调用自身的 token，却不带 turn 和 step，因此它的费用从来进不了总数；重试或中断的尝试里记录的用量现在同样会被读取，收尾消息若漏掉了用量记录也会回退到它自己数据流里的最后一条。Overview 与 Sessions 页的数字依旧一致，已入库的记录会重新解析。另外，一个日志文件若先损坏、再恢复、随后又损坏，第二次损坏在该进程剩下的生命周期里不会再输出任何日志；现在一次成功读取就会忘记这个文件。
- 侧边栏旁边的标签行不再于宽屏上重新出现。让它隐藏的那条规则此前已被写成无效选择器，浏览器直接丢弃且毫无提示。多处指向错误文本的无障碍名称也一并修正：配额间隔控件原本播报“saved interval”，而它自己的标签写的是“Poll every”；还有一个关闭按钮的图标被它自己的标签文字替换掉了。
- 未翻译的页面与翻译后的页面不再各说各话。若干内置的英文兜底文案与英文词典出现了偏差，于是每种语言都会先短暂显示这个过时的写法，再被翻译流程覆盖 —— 例如侧边栏写着 “What's New”，而词典里是 “What's new”。现在每条兜底文案都与自己对应的键保持一致。
- 支撑翻译的那些检查现在不再只能在编写它的机器上通过：仪表盘的测试套件此前用 Windows 的区域编码去解码 Node 的输出，中文、日文和 emoji 都会乱码；终端仪表盘的一处检查则在其请求尚未完成时就读到了数值。

## 2.6.10 - 2026-10-04

### 新增

- 新增 Freebuff Desktop 数据源。Tokdash 会读取该桌面应用按项目存放的 SQLite 数据库，既统计每一轮助手消息的用量，也统计自动任务循环自身发出的模型调用，并按应用自身的记录方式把缓存输入与推理 token 拆分出来。走 claude-code 或 codex harness 的轮次会被跳过，因为那部分用量已经以 Claude Code 和 Codex 的形式出现。Freebuff 按“一小时的模型时长”计费而不是按 token，因此这里显示的费用只是与 API 等价的估算，并非账单。
- 仪表盘的 Tailwind CSS、Chart.js、Three.js 和 Flatpickr 改为从安装包里加载，不再依赖 CDN，完全断网时渲染效果也一模一样。Google Fonts 仍从远程加载。加载顺序与行为都没有变化，这些库文件也同以往从 CDN 加载时一样，会被浏览器缓存一年。

### 调整

- Overview 的 Avg Cache Hit Rate 卡片不再在数字下方重复自己的标题。

### 修复

- 在保留 /tokdash 前缀转发的反向代理后面，静态资源现在可以正常加载。此前在这类代理下，所有样式表、脚本和图标都会返回 404，页面样式只剩一半；现在代理无论保留还是剥掉前缀都能正常工作。Tailscale Serve 不受影响。
- EST. agent time 与 Avg Cache Hit Rate 两张卡片不再显示凭空编造的数字。它们的角标原本硬编码为 -61% 和 92%，页面上没有任何东西能更新它们，于是所有用户、任何时间范围、任何语言看到的都是同一组数字，就摆在真实数值旁边。两个角标都已删除，并且新增了一条测试，禁止 Overview 的 KPI 卡片里出现任何硬编码数字。

## 2.6.9 - 2026-10-03

### 新增

- 由 setup 托管的 Linux 安装可以在仪表盘里直接更新。当响应的进程证明自己正是 tokdash setup 装上的那个服务时，更新弹层就会给出升级入口，升级由一个在服务之外启动的辅助进程执行，因此能在它自己引发的重启中存活；升级前先备份使用量数据库，每条失败路径都会尝试把服务重新拉起。其余安装仍然保留可复制的 tokdash update 命令。从远程浏览器访问该入口需要显式开启：在 TOKDASH_UPDATE_ORIGIN 中固定确切的 HTTPS 来源，并输入一次在主机上用 tokdash update-enroll 生成的一次性配对码。
- 已支持读取 DeepSeek Harness 第 3 和第 4 代日志格式。上游重命名了 session 文件，导致升级 dsh 之后 DSH 数据源被清空。现在两代格式都会按后缀匹配；带 seed 但缺少 inherited 标记的日志不计费，而不是靠猜测。
- CDN 加载失败时会明确告知。Tailwind、Chart.js、Three.js、Flatpickr 和 Google Fonts 各自检查本该提供的能力，缺失时以仪表盘当前语言弹出一张可关闭的提示。如果失败的是 Flatpickr，日期范围选择器会一并停用，而不是留下一个点了没反应的按钮。

### 调整

- README 以两条命令的快速上手开篇，并介绍这个包真正提供的四种视图：WebUI、TUI、Companion 和 Statusline。参考表格移至 docs/ 下，各自只保留一份；所有截图都改由带种子的测试数据重新生成，而不是取自真实账号；六个语言版本逐标题对齐新结构。

### 修复

- 无法读取的 DeepSeek Harness 日志不再丢失已存储的记录，也不再悄无声息：既有记录会保留，问题会以同一套措辞在 Overview 和 Sessions 页各报告一次。损坏的中间帧只影响其内部的记录，周围的批次仍然计入。
- Overview 与 Sessions 页现在对一个 DeepSeek Harness session 只认定一个胜者，同一份数据被复制成两份且记录了不同用量时，不会再因为你正在看的是哪个页面而算出不同的费用。
- 在使用量数据库关闭的情况下，被复制的 Reasonix 日文件只计费一次；删除副本也不会再丢掉原文件已经记录的使用量。
- Antigravity 的 gemini-3.8-flash-n 现在按 gemini-3.8-flash 计价，不再显示 $0.00。
- 日期范围的每个边界都按各自那一天所处的 UTC 偏移解析。在实行夏令时的时区，跨越时钟变更另一侧的范围会偏差一小时：深夜的事件落在窗口之外，却又被热力图计入。如今时钟变更的那一天恰好是 23 或 25 小时，Overview、Sessions 与热力图口径一致。
- 使用量存储读取失败会被记录到日志，而不再被吞掉——损坏或被锁定的缓存会让每个请求都退化成一次完整重扫，现在这一点终于可见。它刻意不出现在 API 响应中：回退得到的答案是完整的，将其标记为异常反而会让仪表盘在数据库修复之前一直停留在过期数字上。
- Overview 上没有数据的范围显示“暂无数据”，不再一排卡片从 0 往上数。数字滚动动画也不再从错误的基数续算、从上一个范围的总数往回数，或在卡片里闪出一个比卡片本身还宽的带小数点的数值。
- Pi 的 fork 回放测试在所有时区都能通过。它原先把测试数据标记为 21:33 UTC，却按固定的本地日期查询，因此在 UTC+2:27 以东的机器上会查错的日期，等于在世界大部分地区白白关掉了 fork 回放的回归保护。

## 2.6.6 - 2026-09-28

### 新增

- 桌面仪表盘新增侧边栏：Overview、Sessions Explorer、Stats & Heatmap、Usage Report、Quota & Budgets、Servers 与 Pricing DB 作为导航项，底部是 What's New 与设置，页眉提供深浅色快速切换，Sessions 页的筛选行则按所选周期内真正有会话的工具生成。手机宽度保留原有标签栏，并补上原先藏在侧边栏里的齿轮与 What's New 图标，因此 768px 以下仍可打开设置与切换语言。
- 会话详情现在会呈现各工具已经记录下来的信息：Hermes 会话的工作目录项目名与 git 分支、每个会话的工具调用与消息条数、配置档名称，以及 Hermes 与 Antigravity 会话的纯元数据消息时间线（角色、大小、token 数、时间戳、工具名）。转录文本不会读入 API，只有这些度量值会被送出。
- Overview 新增 Token Composition 区块，把当前时间窗的 token 拆分为 prompt、cache、output 与 reasoning，并在旁边给出缓存命中的现金价值。tokens_reasoning 现在经由计算层聚合，因此各部分相加等于总量。

### 调整

- 设置改为从侧边栏入口以弹窗形式覆盖在页面上。此前它渲染成挂在页眉下方的面板，而按钮却位于侧边栏底部，相隔近一屏；设置与 What's New 也各有两份（页眉一份、侧边栏一份），现在各保留一份。
- 浅色模式不再是"深色油漆刷在浅色墙上"。改版中硬编码的表面（#0d121f 卡片、#090d16 会话抽屉、白色半透明分隔线、深色系文本配默认 Paper 主题）已映射到主题令牌，因此卡片、KPI 网格、抽屉与滚动条会跟随所选样式主题，而不再是纯黑。每个可见字符串都经过实际测量而非目测：仪表盘在浅色与深色模式下都不再有低于 WCAG AA（4.5:1）对比度的文本，包括深色配色下几乎不可见的那些标签。
- 能耗/kWh 估算已移除。它的每 token 焦耳系数引用了仓库之外的研究笔记，而为其供数的模型匹配器会把 Kimi 识别为 llama-405b、把 Gemini 的任何 "pro" 识别为 claude-opus；Tokdash 不发布无法溯源的数字。成本本来就是那个一直存在的代理指标。
- 侧边栏与页眉的版本号改为读取运行中的包，而不是写死、且写下时就已过时的字面量。
- Z.ai 配额卡片改用 ZCode 标志，不再使用灰色字母占位块。该轮询本来就是从 ZCode CLI 自身的配置中读取 Z.ai 密钥，因此服务商映射表把 zai 指向包内已有的 ZCode 条目，而不是再打包一份同样的图形；Z.ai 卡片仍保留自己的标题，因此读起来依旧是 Z.ai。
- 不带子命令直接运行 tokdash 现在打印一屏命令卡（十一个动词分为四组，每组一行），而不是完整的参数参考。--help 仍是完整参考、仍列出每一个参数，但用法行收成一行，参数按小节排列，每节标题会列出读取它的每个动词，因此十二个参数不必各自重复一行 For tokdash quota consent。出错时同样只打印这段简短用法。

### 修复

- Hermes 会话保留真实的最后活动时间。此前某个版本的实现会在每个会话的 ended_at 处追加一个零 token 回合来拉长活跃时长，等于凭空记入消息之间数小时的空闲；伪造的回合已移除，Hermes 解析器版本保持为 1，因此升级后既有的解析缓存继续可用。
- Pi 分叉的重放只计一次。Pi 分叉会把父会话中已计费的助手事件复制进新的会话文件，而这些副本此前被当作新的用量读取——分叉一次就会抬高该会话触及的每一个汇总，分叉还会以整段历史都是重放出来的行出现在 Sessions 中。现在沿 parentSession 头部解析血缘，每个事件以经佐证的不可变字段作为键，因此原始会话拥有已记录的计费，后代只贡献自己的新工作，只有重放而没有新内容的会话会直接消失。血缘关系持久化在每个文件的缓存元数据中，因此删除祖先日志后重新打开仪表盘不会让同一次重放获得新的身份；Pi 解析器版本升到 2，会重建一次 v1 记录。

相关 PR：#110、#123、#125、#126
